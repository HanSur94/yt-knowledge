# Stage 9a — Implementation Readiness

**Verdict: not ready.** The plan names files and functions but leaves the worker, the wire format, the FTS keying and the auth mechanism undecided; a fresh implementer would have to design four subsystems and invent a schema field to make retries work.

Range reviewed: `yt-knowledge.md` lines 388-535 (phase 0 through Verification Plan), with earlier sections read as context.

## Findings

1. **[BLOCKER]** "Phases are ordered so the service is runnable and testable after each one." — `collector.py` / phase order. Phase 1 ships `collector.py` but `app.py` (which owns `POST /import`, `GET /queue`, `GET /healthz`) is Phase 2. Phase 1's own check, "Then `--push`; `/queue` shows the pending count", targets a route that does not exist yet, so Phase 1 ends with four importable modules and no runnable service. Phase 0 is worse: it builds `CMD ["ytk","serve"]` before `pyproject.toml` or `app.py` exist and has no checkpoint at all (no `docker build`, no `compose up`, no smoke request). Phase 3 holds every test, so Phases 1-2 are verified by nothing.

2. **[BLOCKER]** "`lifespan` starts one asyncio worker task that claims rows, runs fetch then summarize, and sleeps when the queue is empty." — `app.py`. This one sentence is the entire worker and it decides nothing: the order of metadata/transcript/thumbnail/sponsors, where the `duration_s < 120 -> archived` rule is applied, when `fetched` is persisted, how `no_caption` is distinguished from a fetch failure, when `attempts` is incremented, whether a thumbnail failure fails the video, whether summarisation can start while the transcript write is uncommitted, how the blocking `yt-dlp`/sqlite3/httpx calls avoid stalling the event loop, and the idle sleep interval. Every one of those is an architectural choice the implementer must make.

3. **[BLOCKER]** "failed ──attempts < 3──> backed off, then retried at fail_stage" — `db.py`. The data model has no `next_attempt_at` (or equivalent), so "backed off" is unrepresentable: the implementer must invent either a column the schema does not have, or an ordering rule over `fail_stage`/`attempts`, or an in-memory timer that dies on restart. `claim_next(limit)` likewise gives no SQL, no claimable-state predicate, no ordering, no lease/timeout, no rule for whether `attempts` increments at claim or at failure — and its test ("cannot hand the same row to two callers") cannot be written without those decisions. `set_state(video_id, state, **fields)` leaves the allowed field vocabulary and the attempt-bump/no-bump behaviour open, which is exactly where a double-increment or a lost `fail_reason` will land.

4. **[BLOCKER]** "Posts JSONL in batches of 500." — `collector.py` and `ingest.py`. The wire contract is defined on neither side: field names (`url` vs `video_id`+`watched_at`), timestamp encoding (Chromium epoch microseconds vs Safari's 2001 epoch vs ISO), the batch envelope (JSONL stream vs array), the content type, the auth header, and the `POST /import` response body. CUJ 1 requires the response to report "received, merged-into-existing, filtered-short and new", but no response schema exists, and the two files are written in the same phase by an agent that must make both halves agree by guessing.

5. **[BLOCKER]** "`require_session` dependency on everything except `/login` and `/healthz`." — `app.py`. A FastAPI dependency does not run for a mounted ASGI sub-app, so "Mounts the MCP ASGI app at `/mcp`" leaves the MCP surface unauthenticated, contradicting the doc's "including the mounted MCP endpoint". The same dependency also makes the collector path impossible: `POST /import` is supposed to take a bearer token, but a cookie dependency rejects a token-only client. Neither the middleware-vs-dependency split nor the "bearer OR session" bypass is specified, and the signed cookie has no signer in the dependency list (Starlette's `SessionMiddleware` needs `itsdangerous`; hand-rolled HMAC needs a stated scheme).

6. **[BLOCKER]** "the two FTS5 virtual tables and the five sync triggers" — `db.py`. `videos_fts` is declared with no `content=` and `videos` has a TEXT primary key, so nothing in the plan says which row of `videos_fts` belongs to which video; the trigger must write `new.rowid`, and the test "regenerating a summary updates `videos_fts`" cannot be implemented until that key is chosen. The count is also wrong: three triggers for `segments_fts` plus three for `videos_fts` (insert/update/delete) is six, so "five" silently drops one delete path. And `summaries` is `UNIQUE(video_id, lang)` while `videos_fts` is "one row per video" — which language wins the FTS row is a decision nobody has made.

7. **[BLOCKER]** "reusing the layout from `document-knowledge-pipe`" — `app.py`. This is a design choice wearing an instruction's clothes: the target project is greenfield and that layout is not described, not linked, and may not be visible to the implementer. Even with the repo in hand, `<date>-<slug>.md` never says which date (published, first seen, last watched), how the slug is computed (lowercase? ASCII-folded German? length cap?), what happens on collision, what the frontmatter keys are, what `registry.md` contains, or whether a 4,253-file export is synchronous inside the request.

8. **[MAJOR]** "Helpers: `upsert_video(rec)`, … `set_state(...)`, `claim_next(limit)`, `search(q, filters)`" — `db.py`/`fetch.py`/`app.py`. No file is assigned the writes for `chapters`, `skips` or `summaries`; no file is told to persist `thumb_path`, `language`, `published_at` or `first_seen`/`last_seen`. Separately, "INSERT OR REPLACE on `(video_id, start_s)`" is claimed to mean "retry replaces, never duplicates", but a re-fetch that returns fewer segments leaves the old tail in place; the plan never says to delete the video's segments before insert, and the test only counts rows.

9. **[MAJOR]** "capping at roughly 12k tokens by sampling the opening and closing thirds of long transcripts" — `summarize.py`. "Roughly" is a decision: characters divided by four, a tokenizer, or a word count? "Opening and closing thirds" leaves the middle third — often the argument — silently dropped, with no rule for how a partial segment is cut at the budget edge. The prompt text itself (the artifact the "names their central claim" goal depends on) is never written, the exact JSON shape of `bullets` (key names, timestamp format) is not fixed, and `bullets_json` storage format is undefined. The request is equally open: endpoint path, whether `response_format` is used, temperature, `max_tokens`, timeout, and whether a 5xx or timeout is retried (only malformed JSON gets "one retry").

10. **[MAJOR]** "dropping sponsor spans" — `summarize.py`. The doc says "sponsor, intro and self-promo spans removed", the plan says only sponsor, and `sponsors()` never says which SponsorBlock categories to request. The cut is also undefined at the boundaries: does a caption line that starts before `start_s` and ends after it get dropped whole, trimmed, or kept? The test asserts "cutting exactly the overlapping caption lines" against an algorithm that has not been chosen, so the test's expected value is unknowable.

11. **[MAJOR]** "`search(q, filters)`" — `db.py`. `filters` has no key set, the return type is undefined (a flat list? two lists? dicts with `video_id`, `score`, `snippet`, `start_s`?), and the stated behaviour "ranks each with bm25() and returns summary-level hits above transcript-level ones with duplicates collapsed" is a design problem, not an instruction: bm25 scores from two different indexes are not comparable, so the implementer must invent bucketing or normalisation. Nothing says how user input becomes a valid MATCH expression — raw `postgres index bloat` is fine, but an apostrophe or a `(` raises `sqlite3.OperationalError`, so quoting/escaping is an unstated requirement of the headline search feature.

12. **[MAJOR]** "`transcript(video_id)` … raising `NoCaption`" — `fetch.py`. No exception taxonomy exists: which errors are terminal (`no_caption`, deleted, private, age-restricted) and which are retryable (`429`, timeout, `5xx`) is the single most consequential decision for a 4,253-video backfill, and it is left open, as is the transcript language preference (the corpus is 2,776 EN / 981 DE, and `YouTubeTranscriptApi().fetch()` defaults are a choice). `metadata()` shells `yt-dlp` with no timeout, so one hung process blocks the only worker forever. `NoCaption` itself has no module, no base class, no message contract.

13. **[MAJOR]** "`upsert_video(rec)`" — `db.py`. Conflict behaviour is unspecified, and it is load-bearing: a re-import must not reset a `ready`, `archived` or `no_caption` row to `pending` (the doc promises "a re-import cannot resurrect them"), yet the plan never says which columns update on conflict or whether `state` is preserved. `rec`'s keys are also undefined, so the caller and callee are written against different guesses.

14. **[MAJOR]** "`add_watch(video_id, at, dwell, src)`" — `db.py`/`ingest.py`. `at` has no type (ISO string? epoch? datetime?), and the 90-minute merge is a timestamp comparison, so the format must be pinned: "UTC ISO-8601" allows both `Z` and `+00:00`, and string comparison across those two forms is wrong. `dwell` has no null convention even though the ingest rule depends on its absence ("if `dwell_s` is absent"), and "A dwell longer than 4 hours is stored but flagged" has no column to hold the flag.

15. **[MAJOR]** "Session middleware backed by a signed cookie" — `app.py`. Cookie name, `max_age`, `HttpOnly`/`SameSite` (both stated in the doc) and `Secure` (must be off over LAN HTTP, or login silently fails) are unstated; the login form's field name, the failure response (401 page vs re-render), the redirect target, the constant-time comparison wiring, logout behaviour, and session invalidation on secret change are all invented. This is the only control protecting the whole archive.

16. **[MAJOR]** "Module constants `SLEEP = 0.5` and `MAX_ATTEMPTS = 3` as the only tuning knobs." — `fetch.py`/`app.py`. This contradicts the config table, which already ships `YTK_SLEEP` and `YTK_CONCURRENCY`; two sources of truth for one value. `YTK_CONCURRENCY` also contradicts "one asyncio worker task" (one task cannot keep N rows in flight), and `YTK_BIND` defaults to `192.168.178.40:8488`, an address the container does not own — uvicorn will refuse to bind under compose unless the plan says to override it to `0.0.0.0` and let the port mapping do the LAN binding. `YTK_DIGEST_CRON` needs a cron parser that is in no dependency list, and `digest(rows)` never mentions the LLM call that the digest table's `model` column implies.

17. **[MAJOR]** "`/queue` shows the pending count and the filtered count, and the two together equal what the collector reported." — `app.py`/`db.py`. Rejected watches are "counted and dropped", so the filtered count is never stored and `/queue` cannot display it without a counter the schema does not have. The arithmetic is also wrong as stated: the collector reports 4,975 visits and 4,253 distinct videos, while the server's new+merged are per-visit figures — "the two together equal what the collector reported" cannot be evaluated without saying which of the two numbers is meant.

18. **[MAJOR]** "**Type / Scope**: The only tests. Network-free." — `tests/`. The plan's `mcp_server.py` section promises a test that "inspects the registered tool names against a fixed allowlist", but no third test file is in the plan, so the "no write tool" guarantee has no home. Claims with no test at all: the post-fetch archive rule (`duration_s < 120`, never re-summarised, still searchable), `segments_fts` staying in sync when segments are replaced or deleted, retry/resume-at-`fail_stage`, digest idempotency per ISO week, the whole access-control surface including `/mcp`, and the `hqdefault` thumbnail fallback. The id-validation test is parse-level only — nothing tests that `/v/{id}`, `get_video(id)` and the thumbnail path reject `../` before a filesystem write.

19. **[MAJOR]** "Jinja templates rendered server-side with HTMX attributes for search and pagination." — `templates/`. No template receives a documented context, so `app.py` and six templates must agree on variable names by luck. No partial/fragment routes are defined for the HTMX attributes, no `HX-Request` handling is specified, and htmx has no stated source — a CDN script tag breaks the NAS's offline posture. `static/app.css` has no mount, and there is no route or mount at all for thumbnails, so `thumb_path` cannot be displayed (and a `StaticFiles` mount would bypass the session dependency, repeating finding 5).

20. **[NIT]** "Confirm segment counts are in the measured 154-205 range" — Verification Plan. That range came from 14 sampled videos; 20 arbitrary rows from a 4,253-video corpus will include short videos with 40-60 segments and fail the check spuriously. State it as a per-video sanity check (non-zero, increasing `start_s`) plus a median. Likewise "run the worker on 20 videos first" has no mechanism — no `--limit` flag, no env var, no stated way to hold the other 4,233 rows back. And "under one second" has no measurement procedure against a built index.

21. **[NIT]** "`metadata(video_id)` shelling `yt-dlp --dump-json --skip-download`, parsing duration, channel, channel_id, publish date, chapters, language and description." — `fetch.py`. The field mapping is not given: yt-dlp returns `upload_date` as `YYYYMMDD` and chapters as `{start_time, title}`, and the plan's own rule says every timestamp is stored as UTC ISO-8601. The transformation and the null handling (missing `language`, missing `chapters`) are left to the implementer.

22. **[NIT]** "`HEALTHCHECK` against `/healthz`" — `Dockerfile`. `python:3.12-slim` has no `curl` or `wget`, so the check needs an inline `python -c urllib` request; the image also has no non-root user, no pinned versions, no `.dockerignore`, no `pip install .` line even though `CMD ["ytk","serve"]` requires the console script, and it installs `browser-history` into a container that never reads a browser.

23. **[NIT]** "`summarize()` posts to the configured OpenAI-compatible base URL." — `summarize.py`. The signature has no prompt parameter, so `build_prompt`'s output has nowhere to go; the caller (`app.py`) then has to invent `summarize(prompt)` or `summarize(video, segments, ...)` anyway. Return type is likewise undefined, which decides how `bullets_json`, `tags_json`, `model` and `created_at` reach the row.

24. **[NIT]** "with an HTML fallback for `watch-history.html`" — `ingest.py`. The trigger condition is unspecified (JSON member absent vs member present but unparsable), as is the HTML mapping: the `Watched ` title prefix, the channel from the second `<a>`, and the timestamp class are all guesses. `parse_jsonl(body)` also does not say whether `body` is `bytes` or `str`.

Strongest counter-argument: everything above the plan — the data model, the state machine, the API surface, the filter rules and the config table — is unusually precise for a design doc, and a competent Python engineer would fill the gaps with ordinary FastAPI/SQLite choices in an afternoon; the plan's thinness is arguably just the architecture section doing the work twice. That defence fails on three points where no conventional default exists: a retry backoff with no column to hold it, a `videos_fts` row with no key to its parent, and a mounted MCP app that the plan's own auth mechanism cannot protect. Those are not underspecified prose, they are missing decisions that produce silent data corruption or an unauthenticated endpoint.
