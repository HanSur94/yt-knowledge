## Findings

1. **[BLOCKER]** `mcp_server.py` names a class that no longer exists. `FastMCP("yt-knowledge")` on an unpinned `mcp` install resolves to 2.3.0, where the class is `MCPServer`. Correction: `from mcp.server import MCPServer` and `mcp = MCPServer("yt-knowledge")`, or pin `mcp>=1.30,<2` in `pyproject.toml` and keep the v1 code (`mcp==1.30.0` still ships `mcp/server/fastmcp/server.py` with `class FastMCP` and `def streamable_http_app`). Unpinned `mcp` plus v1 code is a `ModuleNotFoundError` on line one.

2. **[BLOCKER]** "Mounts the MCP ASGI app at `/mcp`" is wrong three ways and produces a dead endpoint. `streamable_http_app()` returns a Starlette app whose only route is `/mcp`, so `app.mount("/mcp", inner)` serves `/mcp/mcp`; `POST /mcp` 307-redirects to `/mcp/` and 404s. A mounted sub-app's lifespan never runs, so the session manager is never started → `RuntimeError: Task group is not initialized. Make sure to use run().` And DNS-rebinding protection defaults to `TransportSecuritySettings(enable_dns_rebinding_protection=True, allowed_hosts=[])`, so a request to `http://nas:8488/mcp` gets `421 Invalid Host header`. Official v2 recipe (`py.sdk.modelcontextprotocol.io/v2/run/asgi/`, "the line everyone forgets"): mount at `"/"` with the default path — `app.mount("/", mcp.streamable_http_app(transport_security=TransportSecuritySettings(allowed_hosts=["nas:8488","192.168.178.40:8488"], allowed_origins=["*"])))` — and in the FastAPI `lifespan`, `async with mcp.session_manager.run(): yield`. Note `mcp.session_manager` only exists after `streamable_http_app()` has been called, so build the app at module level.

3. **[BLOCKER]** `INSERT OR REPLACE` on `segments` corrupts `segments_fts` silently. SQLite fires DELETE triggers for REPLACE-conflict deletion **only when `recursive_triggers` is ON** (default OFF). Measured with the doc's schema and triggers: after one refetch of the same `(video_id, start_s)`, `segments` holds `id=2` while `segments_fts` holds rowids `[1, 2]`; joining search hits back gives `[(1, None), (2, 'bloat')]` — a phantom hit whose text is NULL, i.e. a search result with no segment. Retries after an interrupted transcript write grow the phantom set without bound, and the plan's own test ("a rejected refetch of segments leaves the same row count") passes while it happens, because `segments` really is unchanged. Three working fixes, pick one: (a) `PRAGMA recursive_triggers=ON` in `connect()` [measured: leaves `fts_ids=[2]`]; (b) write segments as `INSERT ... ON CONFLICT(video_id, start_s) DO UPDATE SET text=excluded.text` plus an `AFTER UPDATE` trigger that deletes `old.id` and inserts `new.id` [measured: id preserved, index clean]; (c) explicit `DELETE` then `INSERT`. Do not rely on `INSERT OR REPLACE` + an insert-only trigger.

4. **[MAJOR]** `itsdangerous` is absent from `pyproject.toml` and is not pulled by `fastapi` or `starlette` (it lives only in starlette's `full` extra: `itsdangerous; extra == 'full'`). `from starlette.middleware.sessions import SessionMiddleware` → `ModuleNotFoundError: No module named 'itsdangerous'`. The whole auth story ("Session middleware backed by a signed cookie") does not import without it. Add `itsdangerous` (2.2.0 current) or sign the cookie yourself with `hmac` + `secrets.compare_digest`, which the design already half-does.

5. **[MAJOR]** The documented gate cannot cover `/mcp`, and raising `HTTPException` from middleware does not work. FastAPI `dependencies=[Depends(require_session)]` are router-scoped; a `Mount` is not a route with dependencies — measured `GET /mcp/` returned 200 with no cookie while `GET /library` returned 401. Separately, `HTTPException` raised inside a `BaseHTTPMiddleware` is not converted by `ExceptionMiddleware` (which sits inside it): measured **500**, not 401. Correction: one app-level middleware that, for every path except `/healthz` and `/login`, reads the cookie and returns a `RedirectResponse("/login", 303)` (browser routes) or `JSONResponse({"error":"unauthorized"}, 401)` (`/mcp`) — return the response, never raise — plus keep the dependency as defence in depth. Related design consequence the plan does not address: an MCP client registered "by URL in Claude or Codex" cannot obtain a cookie from an HTML login form, so `/mcp` must also accept an `Authorization: Bearer $YTK_SECRET` header, or CUJ 4 cannot be executed as written.

6. **[MAJOR]** `YTK_BIND=192.168.178.40:8488` cannot work as one string, and cannot work as an address inside a bridge container. `uvicorn.run` takes `host` and `port` separately; nothing parses `host:port`, so the string reaches `socket.bind` as a hostname and fails. Even split, binding to the NAS LAN IP from inside a container whose only interface is `172.x` fails with `OSError 49 Can't assign requested address` (measured with a non-owned address on this host). Correction: keep `YTK_BIND` as `host:port` but split it in `serve` (`host, _, port = YTK_BIND.rpartition(":")`), default it to `0.0.0.0:8488`, and enforce the LAN-only rule with the compose port mapping `192.168.178.40:8488:8488` instead of with the bind address. `network_mode: host` is the alternative, but then don't also publish ports.

7. **[MAJOR]** `POST /import` cannot be declared twice for JSONL and multipart. FastAPI dispatches on path only: measured, both handlers registered on `/import`, and a multipart upload reached the JSONL handler (`{"handler":"jsonl"}`). If the multipart handler is declared with `UploadFile = File(...)`, JSONL posts get 422 instead. Correction: one handler, `async def import_(request: Request)` that branches on `request.headers["content-type"].startswith("multipart/form-data")` — `await request.form()` for the zip, `await request.body()` for JSONL — and calls `parse_takeout` or `parse_jsonl`. No `File(...)` parameter on that route.

8. **[NIT]** `upload_date` is `YYYYMMDD` (`'20261028'`), not ISO-8601, so the "every timestamp is stored as UTC ISO-8601" rule needs an explicit `strptime(..., "%Y%m%d")` step; `chapters` is present but `None` whenever the video has no markers (the Fireship test video), so the chapter step must tolerate `None`, not assume a list. `timestamp` (epoch) is also available and less error-prone.

9. **[NIT]** The `rebuild` command is only unnecessary because `init()` creates `segments_fts` before any segments exist. Any later migration that adds or recreates an external-content FTS table over populated `segments` will return zero hits until `INSERT INTO segments_fts(segments_fts) VALUES('rebuild')` runs — measured: 0 matches before, 1 after. Cheap insurance: run `rebuild` (or `integrity-check`) once per version bump in the `user_version` migration branch.

10. **[NIT]** `visits.visit_duration` is **microseconds** (measured sample `322190648` for one visit ≈ 322 s; another `1057364` ≈ 1.06 s). The design stores `dwell_s` and flags anything over 4 hours, so a missing `/1_000_000` would flag the entire archive rather than fail loudly.

11. **[NIT]** `YTK_DIGEST_CRON="0 3 * * 1"` has no parser in the dependency list and none in the stdlib — Python has no cron expression support (`sched` is interval/delay only). Either add `croniter` or write the four-way split for this one fixed five-field format and reject anything else. Same gap for the verification plan: `pytest` and `ruff` are invoked by "Build"/"Lint" but are not declared (dev extra), so `pip install -e .` then `pytest tests/ -q` fails on a clean machine.

12. **[NIT]** `youtube-transcript-api` 1.2.4 raises a family, not one exception: `TranscriptsDisabled`, `NoTranscriptFound`, `VideoUnavailable`, `VideoUnplayable`, `AgeRestricted`, `PoTokenRequired`, `IpBlocked`, `RequestBlocked`. `NoCaption` should be raised for the first three (permanent, never retry) and `IpBlocked`/`RequestBlocked` must map to a retryable `fail_stage=fetch`, otherwise an IP block permanently marks ~4,000 videos `no_caption` on the first backfill night.

Strongest counter-argument: Items 1, 2, 5 and the FTS5 core are exactly right, the design's riskiest guess (`youtube-transcript-api`'s `.fetch()`) is the correct current API, and every finding above is a five-to-fifteen-line correction rather than a redesign — except finding 2, which is the one an implementer would lose a day to, because the endpoint returns 307/404/421/`RuntimeError` depending on which of three separate mistakes they notice first, and the SDK's own docs describe all three as the standard traps.
